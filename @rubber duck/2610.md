> NRVO

함수 안에서 만든 지역 변수를 값으로 반환할 때는 `std::move`를 붙여야
복사 비용을 줄일 수 있을 것처럼 보인다. 

지역 변수 `s`는 lvalue이고 함수가 끝나면 소멸하기 때문이다. 

하지만 `return s;`처럼 지역 변수의 이름을 그대로 반환하면, 
컴파일러는 호출자가 받을 결과 객체의 저장 공간에 `s`를 직접 생성할 수 있다. 
이를 NRVO(Named Return Value Optimization)라고하며, 
복사나 이동 자체가 생략되므로 `std::move(s)`를 붙일 필요가 없다.

반대로 `return std::move(s);`처럼 
반환식이 단순한 변수 이름이 아니면 NRVO의 대상이 되지 않을 수 있고, 
그 경우에는 `s`를 이동한 뒤 지역 객체를 소멸시키는 추가 작업이 필요해질 수 있다. 

따라서 반환할 지역 변수라면 먼저 `return s;`를 사용하고, 실제로 복사나 이동이 발생하는지와 성능을
프로파일링하는 것이 좋다. 

다만 NRVO는 모든 반환식에 적용되는 것은 아니며, 서로 다른 지역 변수를 조건에 따라 반환하는 경우처럼 
컴파일러가 하나의 객체로 합치기 어려운 상황에서는 적용되지 않을 수 있다.

```cpp
#include <utility>

struct Widget {
    Widget();
    Widget(const Widget&); // 복사 생성자
    Widget(Widget&&);      // 이동 생성자
};

Widget make_widget()
{
    Widget w;
    return w;              // NRVO가 적용될 수 있음
}

Widget make_widget_with_move()
{
    Widget w;
    return std::move(w);   // NRVO가 적용되지 않을 수 있음
}
```

두 함수 모두 문법적으로는 `Widget`을 반환하지만, 첫 번째 함수에서는
호출자의 결과 객체가 만들어질 공간에 `w`를 직접 생성할 수 있다. 

두 번째 함수에서는 `std::move(w)`가 `w`를 xvalue로 변환하므로 이동 생성이
선택될 수 있지만, 이것은 NRVO와는 다른 동작이다. 

또한 반환 대상이 `Widget`처럼 이동 비용이 큰 타입이라면 `std::move`가 성능을 개선하기보다
오히려 NRVO를 막아 성능을 떨어뜨릴 수 있다.
